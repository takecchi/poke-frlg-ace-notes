# payloads: ACEペイロード実例

**※ 日本語版には2つの独立したACEシステムがある。混同注意。**

| システム | 使用Box | トリガー | 用途 | 詳細 |
|---------|---------|---------|------|------|
| **A: 直接ARM実行** | Box1-5 (ARM命令+データテーブル) | 天元 or みみぅむぅの入れ替え | ポケモン生成 (0xFFC9, 0x4F90, アチャモ等) | ace_methods.md, glitch_species_calc.md |
| **B: 汎用コード環境** | Box1(-2)=スクリプト, Box11-13=ブートストラップ | みみぅむぅの入れ替え | ゲーム内蔵スクリプト呼び出し (所持金, 殿堂入り, 野生戦等) | 本ファイル下記 |

- **システムA**と**システムB**はBox名セットが完全に異なる。同時使用不可(切り替えて使う)
- システムBはコードポケモン2体(Box12 Slot30, Box14 Slot28)の配置が必要

## 日本語版: 汎用コード環境 (システムB・デテロニー氏考案)

0xFFC9「みみぅむぅ」生成後、さらに2体のコードポケモン(フシギダネ型バグポケ)を生成し
特定のボックス位置に配置することで、Box1の名前を変えるだけでゲーム内蔵スクリプトを
呼び出せる環境を構築する技術。

### 構築手順 (Switch版 日本語LG)

#### Step 1: コードポケモン「ふガでシ」の生成

ボックス名を以下に設定:
```
Box 1: かッンNくぐズチ
Box 2: アリG空み空C
Box 4: アエぢいい
Box 5: 空ぶガでシて空空
Box 6: アあいあ空
```
みみぅむぅと適当なポケモンを入れ替え → 手持ち2番目に「ふガでシ」(フシギダネ型バグポケ)が生成。
→ 一旦Box1等にしまっておく。

#### Step 2: コードポケモン「ャl」の生成

ボックス名を以下に変更:
```
Box 1: かッンNくぐズチ
Box 2: アリG空み空C
Box 4: アエぢいいN
Box 5: ャl
Box 6: アあいあ空
```
みみぅむぅと適当なポケモンを入れ替え → 手持ち2番目に「ャl」(フシギダネ型バグポケ)が生成。

#### Step 3: コードポケモンの配置

- 「ャl」→ Box14 Slot28
- 「ふガでシ」→ Box12 Slot30

#### Step 4: ブートストラップ用ボックス名の設定

```
Box 11: うッゃNさRまK
Box 12: ア空み空Cあい
Box 13: ャなうい7そ空う
```

→ 汎用コード環境の構築完了。

### 使用方法

Box1の名前を変更し、みみぅむぅ(0xFFC9)の入れ替えを実行するだけでスクリプトが呼ばれる。

### 動作の仕組み

- Box12 Slot30 (ふガでシ) = ACE実行開始地点付近のコードポケモン
- Box14 Slot28 (ャl) = 後段の処理を担うコードポケモン
- Box11-13の名前 = ブートストラップコード (コードポケモンとBox1を橋渡し)
- Box1の名前 = ユーザーが指定するスクリプトID/パラメータ

実行チェーン:
```
みみぅむぅ入替 → 0xFFC9のバッファオーバーフロー
→ Box12 Slot30 (ふガでシ) 付近から実行開始
→ NOPスライドでBox名領域に到達
→ Box11-13のブートストラップコード実行
→ Box1の名前をスクリプトID/パラメータとして解釈
→ ゲーム内蔵スクリプト呼び出し
```

### 確認済みスクリプト (システムB、Switch版 日本語LG)

**※ 以下のBox1/Box2はすべてシステムB(汎用コード環境)用。Box11-13ブートストラップ+コードポケモン配置が前提。システムA(直接ARM実行)のBox1-5とは全く別物。**

| Box1の名前 | バイト列 | 結果 |
|-----------|---------|------|
| `ゾ！！！！空` | 90 AB AB AB AB 00 | 所持金 999999 (addmoney) |
| `ダ！！！！空` | 91 AB AB AB AB 00 | 所持金 0 (removemoney) |
| `ゆたあらい` | 25 10 01 27 02 | 殿堂入り (special 0x0110 EnterHallOfFame + waitstate + end) |
| `であ空テ空い` | 44 01 00 63 00 02 | マスターボール99個 (additem 0x0001 qty=99 + end) |

#### Box1→Box2連結スクリプト

| Box1の名前 | Box2の名前 | Box1バイト列 | Box2バイト列 | 結果 |
|-----------|-----------|-------------|-------------|------|
| `あああああじうき` | `あ空あ空` | 01 01 01 01 01 3D 03 07 | 01 00 01 00 | セキチクシティにテレポート |
| `ああああ♀バ空ば` | `空ゆぎあらい` | 01 01 01 01 B6 96 00 46 | 00 25 38 01 27 02 | ミュウツーLv70と野生戦 |
| `ああああ♀ねあお` | `空ゆぎあらい` | 01 01 01 01 B6 18 01 05 | 00 25 38 01 27 02 | アチャモLv5と野生戦 |

※ `空` = 空白文字 (FRLGには漢字がないため、空白を「空」と表記する)

### Box1→Box2連結テクニック

Box名はgPokemonStorage内で連続配置(9バイト/box: 8文字+0xFF終端)されている。
スクリプトコマンドのパラメータが0xFF終端子の位置にちょうど来るようnop(0x01=あ)でパディングすることで、
0xFFをコマンドではなくパラメータとして消費させ、スクリプト実行をBox2へ継続させる。

```
Box1: [nop×N] [コマンド] [param1] [param2]
      ↓ 0xFF終端 = param3として消費される(コマンドとして解釈されない)
Box2: [param4] [param5] ... [end]
```

#### warpteleportの場合 (検証済み)

warpteleport(0x3D)は7パラメータバイト: [group:1] [num:1] [warpId:1] [x:2] [y:2]
nop×5で位置合わせし、warpId(3番目パラメータ)がちょうど0xFF終端に来るよう配置:

```
Box1: 01 01 01 01 01  3D     03      07
      nop×5           warp   group   num
                                          [0xFF = warpId(デフォルト着地点)]
Box2: 01 00  01 00
      x=1    y=1
```

warpId=0xFFはゲーム内部で「デフォルトの着地点を使用」として扱われる。

#### 任意ポケモンとの野生戦 (nop×4ブリッジ、検証済み)

setwildbattle(0xB6) + special StartLegendaryBattle(0x0138)をBox1→Box2ブリッジで1回実行。
nop×4でパディングし、setwildbattleのitem_lo(5番目パラメータ)が0xFF終端に来るよう配置:

```
Box1: 01 01 01 01  B6      [sp_lo] [sp_hi] [level]
      nop×4        swb     species(LE)      lv
                                                    [0xFF = item_lo]
Box2: 00    25      [idx_lo] [idx_hi]  27       02
      itm_hi special(0x0138)           waitstate end
```

item = 0x00FF(有効なアイテムID)。ポケモンの持ち物になるだけで戦闘に影響なし。

**重要: nop×3ではなくnop×4を使うこと。** nop×3だとitem_hi=0xFF→item=0xFF00(無効)でエラーになる。

**任意ポケモンの計算方法**:
1. `species_ids.md` から種族の内部インデックスを調べる
2. Box1: `ああああ♀ [species_lo文字] [species_hi文字] [level文字]`
   - `01 01 01 01 B6 [species:2 LE] [level:1]`
3. Box2: `空ゆぎあらい` (固定: item_hi=0 + special 0x0138 + waitstate + end)

#### 任意の場所へのテレポート計算方法

1. `game_constants.md` から目的地の mapGroup と mapNum を調べる
2. nop×5 + warpteleport(0x3D=じ) + group + num = Box1 (8文字)
3. 0xFF = warpId (自動)
4. x座標(2バイトLE) + y座標(2バイトLE) = Box2 (4文字)
5. 座標が不明な場合はx=1,y=1(あ空あ空)で試す

#### 失敗→解決記録

| Box1の名前 | Box2の名前 | 意図 | 結果 | 原因 |
|-----------|-----------|------|------|------|
| `あああ♀バ空ば空` | `ゆぎあらい` | setwildbattle+StartLegendaryBattle(ミュウツー戦) | エラー | nop×3 → item_hi=0xFF → item=0xFF00(範囲外) |

**解決**: nop×4にすることで0xFFがitem_loの位置に来る。item=0x00FF(255, 範囲内)となり正常動作。
- nop×3: item = item_lo(0x00) | item_hi(**0xFF**) = **0xFF00** → 無効なアイテムID → エラー
- nop×4: item = item_lo(**0xFF**) | item_hi(0x00) = **0x00FF** → 有効なアイテムID → 成功

### 制約

- ゲーム内蔵スクリプトの呼び出しに限定される
- 任意の機械語実行 (PRNG操作、PID書き換え等) はこの環境では不可
- Box1単体: 8バイトまで。Box2連結: パラメータで0xFFを跨ぐ必要あり
- dowildbattle(0xB7)は入力不可バイトのため直接実行不可 → nop×4ブリッジ方式で回避(setwildbattle+StartLegendaryBattle)
- 色違い生成にはHexwriter等のより高度なセットアップが必要

## 実機検証記録 (takecchi: Switch版 日本語LG)

環境: Nintendo Switch / リーフグリーン日本語版
使用チャート: ニドくんチャート (おせけん氏解説動画)

進捗:
1. ニドくんチャートでニドラン♂→中間グリッチ「天元」→0xFFC9「みみぅむぅ」生成 → 完了
2. 汎用コード環境構築 (デテロニー氏手法、コードポケモン2体配置) → 完了
3. スクリプト呼び出し系ACE (所持金MAX: ゾ！！！！空) → 動作確認済み
4. 任意種族生成 (Box4-5書き換え) → アチャモ(0x0118)生成成功 (2026-03)
   - 前提: 手持ち2匹以下(スロット3が空)であること
   - 計算式: checksum = species - 1, Box4末尾とBox5で指定
5. 殿堂入り (ゆたあらい: special 0x0110 + waitstate + end) → 動作確認済み (2026-03)
6. マスターボール99個 (であ空テ空い: additem 0x0001 qty=99 + end) → 動作確認済み (2026-03)
   - 注意: パラメータ省略(であ空い=4バイト)だと不正な数量になる。6バイト必須
7. 任意ポケモンとの野生戦 (nop×4ブリッジ: setwildbattle + StartLegendaryBattle) → ミュウツーLv70で動作確認済み (2026-03)
   - dowildbattle(0xB7)が入力不可のため、setwildbattle+StartLegendaryBattleをBox1→Box2ブリッジで実行
   - nop×4で配置し、item_lo=0xFF(有効ID)としてブリッジ成功
   - nop×3(item_hi=0xFF→item=0xFF00)はエラー。nop×4(item_lo=0xFF→item=0x00FF)で解決
   - ホウエンポケモン(species>0xFF)もアチャモ(0x0118)で動作確認済み
8. 色違い生成 → 未着手 (汎用コード環境では不可、Hexwriter等が必要)

## 非日本語版: Hex Writer汎用ペイロード

手順:
1. Box14にExit Code設定
2. Hex Writerバッドエッグ配置
3. ボックス名に16進コード記述
4. ACE発動 → Hex Writerがボックス名を解読し指定アドレスに書き込み

ボックス名記法(Hex Writer使用時):
- 1文字=1ニブル, 2文字=1バイト, 8文字=4バイト/box
- スペース=バイトスキップ
- 例: `0A1B2C3D` → 0x0A, 0x1B, 0x2C, 0x3D
