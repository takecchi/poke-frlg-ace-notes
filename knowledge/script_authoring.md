# スクリプト作成手順書

汎用コード環境でBox1の名前を変更し、ゲーム内蔵スクリプトを呼び出す手順。

## 手順

### Step 1: やりたいことをスクリプトコマンドに変換

`script_commands.md` から適切なコマンドを選ぶ。

| やりたいこと | コマンド | バイト数 |
|------------|---------|---------|
| アイテム追加 | additem (0x44) | 5 |
| フラグ設定 | setflag (0x29) | 3 |
| フラグ解除 | clearflag (0x2A) | 3 |
| special関数呼出 | special (0x25) | 3 |
| お金追加 | addmoney (0x90) | 6 |
| タマゴ入手 | giveegg (0x7A) | 3 |
| 技変更 | setmonmove (0x7B) | 5 |

### Step 2: パラメータのバイト列を組み立てる

各パラメータは**リトルエンディアン**で配置する。

例: additem マスターボール(0x0001) 99個(0x0063)
```
opcode: 44
itemId: 01 00  (0x0001のLE)
qty:    63 00  (0x0063のLE)
→ 44 01 00 63 00
```

### Step 3: end (0x02) を末尾に付ける

スクリプト終了コマンド。付けないとゲームが暴走する可能性がある。

```
44 01 00 63 00 02
```

### Step 4: 8バイト以内か確認

Box1は8文字(8バイト)まで。超える場合は:
- コマンドを分割して複数回実行
- 不要なパラメータを省略できないか検討

### Step 5: 各バイトを文字エンコーディングで変換

`glitch_species_calc.md` の文字エンコーディング表を使用。

```
44→で, 01→あ, 00→空, 63→テ, 00→空, 02→い
```

### Step 6: 入力不可バイトの確認

以下のバイト値は入力できない:
- 0xB7, 0xB8, 0xB9
- 0xEF-0xFE
- 0xFF (終端子として利用可能だが意図的に入力不可)

該当する場合は別のアプローチを検討する。

### Step 7: Box1の名前を設定して実行

みみぅむぅ(0xFFC9)の入れ替えを実行。

## 複数コマンドの連結

1つのBox名に複数コマンドを詰められる(合計8バイト以内):

```
setflag 0x0820 + setflag 0x0821 + end
29 20 08 29 21 08 02 = 7バイト → けみくけむくい
```

8バイトを超える場合は2つの方法がある:

### 方法A: Box名を変えて複数回実行
```
1回目: けみくけめくい  (バッジ1,3)
2回目: けむくけもくい  (バッジ2,4)
```

### 方法B: Box1→Box2連結 (0xFFブリッジ)

Box名はメモリ上で連続(9バイト/box)。コマンドのパラメータでBox1終端の0xFFを跨ぐことでBox2に到達できる。

**原理:**
```
Box1: [nop×N] [コマンド] [param1] [param2]
      0xFF終端 → param3として消費される(コマンドとして解釈されない)
Box2: [param4] ... [end]
```

nop1(0x01=あ)でパディングし、コマンドの特定パラメータが0xFF(Box1終端)の位置に来るよう調整する。

**設計手順:**
1. コマンドのパラメータ数を確認
2. 何番目のパラメータが0xFFの位置(Box1の9バイト目)に来るか計算
3. 必要なnop数 = 8 - 1(opcode) - 0xFF到達までのパラメータバイト数
4. 0xFFがパラメータ値として許容されるか確認(warpIdの0xFF=デフォルトは可)
5. 残りのパラメータとendをBox2に配置

**検証済み例: warpteleport**
```
warpteleport(0x3D): [group:1] [num:1] [warpId:1] [x:2] [y:2] = 7パラメータバイト
nop数 = 8 - 1(opcode) - 2(group,num) = 5

Box1: あああああじ[group][num]  (nop×5 + 0x3D + group + num)
      0xFF = warpId として消費
Box2: [x_lo][x_hi][y_lo][y_hi]  (座標)
```

## よく使うバイト→文字 早見表

| Byte | 文字 | 用途例 |
|------|------|-------|
| 0x00 | 空 | パラメータの0x00 |
| 0x01 | あ | アイテムID上位バイト等 |
| 0x02 | い | end コマンド / パラメータ |
| 0x08 | く | フラグ上位バイト(0x08xx) |
| 0x25 | ゆ | special コマンド |
| 0x27 | ら | waitstate |
| 0x29 | る | setflag コマンド |
| 0x2A | れ | clearflag コマンド |
| 0x44 | で | additem コマンド |
| 0x7A | レ | giveegg コマンド |
| 0x90 | ゾ | addmoney コマンド |

## 注意事項

- スクリプトコマンドのopcode/special番号/アイテムID等は**GBA版とSwitch版で共通**(実機検証済み)
- メモリアドレス(callnative等)はSwitch版で異なるため使用不可
- パラメータを省略すると後続の終端子(0xFF)等が混入し予期しない動作になる
- 0x00 (nop) は何もしないので、余ったバイトは空(0x00)で安全
